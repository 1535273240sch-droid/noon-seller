## 本次审查解决的规格歧义

- 额度要求同时有“每种分录唯一”和“消费、释放互斥”。数据库同时使用这两项约束，预占发生在余额更新事务里。生成成功后丢弃也已消费。
- 报价示例的 JSON 利用展示精度无法唯一还原利润。实现先将售价入账到分，再独立舍入佣金和税，从入账金额求利润。50 CNY 采购与 10 CNY 运费按 0.5 换算得 30.00 AED 到岸成本，售价 46.15，佣金 4.62，税 2.31，利润 9.22，实际毛利率 19.98%。
- 所有对外有副作用的 POST 通过租户会话和幂等键处理。登录、刷新与纯报价预览按其单独 API 语义执行。开发 webhook 回放优先按事件 ID 去重，同一订单后续新事件仍可进入处理。
- 店铺与仓库能力需要来源证明。手动保存能力或密文，只能记录配置。仓库超时后转对账或人工，禁止使用另一个幂等键重投。
- 当推荐数据源缺失，开发界面标示“模拟数据”；正式环境的验收需要能说明授权范围、采集时间、站点及排名口径的来源。
